# ПРОМПТ ЭТАПА 4 — Telegram-бот

Вставить целиком первым сообщением в **новую** сессию Claude Code в корне
репозитория. Запускать только после того, как этап 3 принят и админка работает.

---

## 1. ROLE

Ты Senior Full-Stack Developer с уклоном в безопасность. Бот получает доступ к
данным чужих людей и к деньгам владельца. Ошибка в проверке прав здесь дороже
любой другой ошибки этого проекта.

## 2. CONTEXT

Тот же репозиторий и стек: Next.js 15 App Router, TypeScript, Prisma 6, Neon,
Vercel. Бот живёт внутри этого же приложения, отдельного сервиса не заводим.

Прочитай перед началом:
- `docs/rebuild/02-ВОПРОСЫ.md` блок 14 — что владелец хочет от бота
- `prisma/schema.prisma` — модели `Lead`, `Payment`, `Note`, `StatusEvent`
- код админки: логика статусов и оплат переиспользуется, а не дублируется

## 3. ГЛАВНЫЙ ПРИНЦИП

**Единственный источник правды — база и CRM.** Бот ничего не хранит у себя, не
ведёт параллельных списков и не становится второй системой управления. Он
удобный интерфейс и канал связи, не более.

Замкнутая логика: Instagram / сайт / Telegram → заявка → общий backend → CRM →
Telegram уведомляет владельца → работа с клиентом → проект → оплата → завершение
→ кейс и отзыв.

Любая функция бота, которую нельзя выразить как чтение или запись через ту же
логику, что использует админка, в бот не попадает.

## 4. STAGE GOAL

После этапа: владелец узнаёт о заявке за секунды и может вести её с телефона;
клиент может написать боту, узнать об услугах, оставить заявку и увидеть статус
своего проекта; посторонний не получает ничего.

## 5. ТЕХНИЧЕСКАЯ ОСНОВА

- `grammy`, версию проверить через `npm view grammy version`
- Работа через **webhook**, не long polling: обработчик
  `app/api/telegram/webhook/route.ts`. На Vercel опрос не работает.
- Секрет вебхука обязателен: при установке передаётся `secret_token`, каждый
  входящий запрос проверяется по заголовку `X-Telegram-Bot-Api-Secret-Token`.
  Не совпал — `401` и выход, до разбора тела.
- Переменные окружения: `TELEGRAM_BOT_TOKEN`, `TELEGRAM_WEBHOOK_SECRET`,
  `TELEGRAM_ADMIN_IDS` (числовые id через запятую, из ответа 14.1). Токен в код
  не попадает никогда.
- Скрипт `scripts/set-webhook.ts` для установки и снятия вебхука.
- Ответ Telegram отдаётся быстро; долгая работа не держит вебхук открытым.

## 6. СХЕМА — что добавить

```prisma
// в model Lead
trackingToken  String?  @unique   // случайные 32 символа, для клиента
telegramChatId String?            // чат клиента, если он писал боту
```

`trackingToken` генерируется криптостойко при создании заявки и выдаётся клиенту
один раз вместе с номером. По `id` заявку через бота не искать никогда:
идентификаторы перебираются.

## 7. ЧАСТЬ ВЛАДЕЛЬЦА

Доступна, только если `from.id` есть в `TELEGRAM_ADMIN_IDS`. Проверка на
**каждое** сообщение и **каждое** нажатие кнопки, а не один раз при `/start`.

### 7.1 Уведомление о новой заявке

Приходит сразу после записи в базу. Поля — из ответа 14.3, по умолчанию: номер,
имя, тип проекта, бюджет, сроки, короткий фрагмент описания. Кнопки: «Открыть
заявку», «Взять в работу», «Ответил».

«Ответил» проставляет `firstRepliedAt` — тот же счётчик, что на главном экране
админки.

### 7.2 Работа с заявкой

По кнопке или командой `/lead ALY-2026-014`:
- карточка со всеми полями заявки
- смена статуса кнопками по цепочке из ответа 13.2; переход пишется в `StatusEvent`
- добавление приватной заметки ответом на сообщение
- кнопки «написать на почту» и «открыть телеграм клиента»
- ссылка на карточку в админке

### 7.3 Быстрые сводки

Команды из ответа 14.4, по умолчанию:

| Команда | Что показывает |
|---|---|
| `/new` | новые заявки |
| `/waiting` | ждут первого ответа |
| `/work` | проекты в работе |
| `/money` | получено за месяц, ожидается, просрочено |

Финансы отдаются **только** админам. Ни при каких условиях никому другому.

## 8. ЧАСТЬ КЛИЕНТА

Для всех остальных. Никаких админских команд, никаких чужих данных.

### 8.1 Приветствие

Текст — из ответа 14.5, слово в слово. Модель тексты не пишет.
Кнопки: «Услуги», «Работы», «Оставить заявку», «Задать вопрос», «Статус проекта».

### 8.2 Услуги и работы

Читаются из базы: опубликованные `Project` и услуги из данных сайта. Отдаются
короткими карточками со ссылкой на сайт. Ничего не дублировать вручную — что
опубликовано в админке, то показывает бот.

### 8.3 Заявка через бота

Пошаговый диалог по тем же полям, что форма на сайте (ответы блока 11).
Записывается **через ту же серверную логику**, что и форма: одна валидация, одна
точка записи. `source` = `telegram`. Незавершённый диалог живёт не дольше часа.
Не больше 3 заявок с одного чата в сутки.

### 8.4 Статус проекта

Клиент присылает номер и токен, полученные при подаче заявки. Бот отвечает
человеческим названием статуса из ответа 14.6.

Жёсткие правила:
- показывается только статус и дата последнего изменения;
- приватная заметка, суммы, бюджет и внутренняя история не показываются никогда;
- не больше 5 попыток ввода токена в час на чат, дальше молчаливый отказ без
  подсказки, что именно неверно;
- токен сравнивается за постоянное время.

### 8.5 Вопрос

Свободное сообщение пересылается владельцу с пометкой, от кого. Владелец отвечает
реплаем, бот доставляет ответ в чат клиента. Историю переписки бот не хранит: это
канал, а не мессенджер.

## 9. АВТОМАТИЧЕСКИЕ СООБЩЕНИЯ

Только те, что владелец назвал в ответе 14.7. Тексты — его слова.

- подтверждение приёма заявки с номером и токеном
- смена статуса, если владелец это включил
- напоминания, если владелец их назвал

Каждое сообщение клиенту отправляется один раз; при ошибке доставки не больше
трёх попыток с нарастающей паузой. Клиент может отключить уведомления командой
`/stop`, и это уважается.

## 10. БЕЗОПАСНОСТЬ

Главный раздел этапа.

- Админство проверяется на каждом сообщении и каждом нажатии кнопки.
- Данным в `callback_data` не доверять: id заявки оттуда проверяется на
  принадлежность и на права, а не используется напрямую.
- Ни одна команда не принимает сырой SQL и не строит запрос конкатенацией.
- Приватные заметки, суммы, расходы и контакты других клиентов не покидают
  админский контур ни в каком виде.
- Секрет вебхука обязателен; без него бот не запускается.
- Токен бота, секрет и список админов только в переменных окружения.
- В логи не попадают тексты сообщений, телефоны, почты и токены — только id
  заявки и класс события.
- Ошибка внутри обработчика не отдаёт стек в чат: клиент видит человеческую
  фразу, подробности идут в лог.

## 11. QUALITY

**Быстро:** ответ на нажатие меньше секунды; тяжёлое выносится за пределы ответа
на вебхук.

**Надёжно:** повторная доставка одного и того же обновления Telegram не создаёт
вторую заявку и не меняет статус дважды — обработка идемпотентна по `update_id`.

**Понятно:** каждое сообщение бота отвечает на вопрос «что дальше»; кнопок на
экране не больше четырёх; длинные списки постранично.

**Без багов:** `tsc` чисто, сборка чисто, вебхук отвечает `200` на любое
корректное обновление.

## 14. CONSTRAINTS

Не заводить отдельную базу для бота. Не хранить заявки в Telegram. Не дублировать
логику статусов и оплат. Не коммитить токен. Не отдавать финансы и приватные
заметки никому, кроме админов из переменной окружения. Не писать за владельца
тексты сообщений. Не использовать long polling. Не сливать в `main` без его слова.
