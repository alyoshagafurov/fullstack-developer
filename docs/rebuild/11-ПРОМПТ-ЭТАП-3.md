## 4. ДИЗАЙН АДМИНКИ

**Не SaaS-дашборд из одинаковых карточек.** Тот же мир «Студийная витрина», но
плотнее: те же токены, тот же Prata на числах и заголовках, тот же Onest в
таблицах, те же пилюли, те же нулевые радиусы.

Правила:
- Числа крупно дисплейным шрифтом. Главный показатель виден с двух метров.
- Асимметрия: главный показатель занимает больше места, чем соседние. Ряд из
  четырёх одинаковых плиток запрещён.
- Воздуха между разделами больше, чем принято в админках. Плотность живёт в
  таблицах, простор — между блоками.
- Тени только под объектами. Панели разделяются линиями `--line` и фоном.
- Цвет по-прежнему один — его нет. Статусы различаются формой и весом: заливка,
  обводка, линия слева, а не зелёный-жёлтый-красный.
- Состояния продуманы все: загрузка скелетоном по форме содержимого, пусто с
  объяснением что сделать, ошибка с действием, успех без модальных окон.

Навигация — узкая колонка слева с разделами и логотипом; на мобильном нижняя
полоса. Все действия достижимы с клавиатуры, у таблиц есть фокус по строкам.

## 5. СХЕМА ДАННЫХ

К моделям этапа 2 добавляются:

```prisma
model Payment {
  id        String   @id @default(cuid())
  leadId    String
  lead      Lead     @relation(fields: [leadId], references: [id], onDelete: Cascade)
  amount    Decimal  @db.Decimal(12, 2)
  currency  String
  paidAt    DateTime?
  dueAt     DateTime?
  kind      PaymentKind @default(STAGE)
  note      String?
  createdAt DateTime @default(now())

enum PaymentKind { PREPAYMENT STAGE FINAL SUPPORT }

model Expense {
  id        String   @id @default(cuid())
  title     String
  amount    Decimal  @db.Decimal(12, 2)
  currency  String
  category  String
  spentAt   DateTime
  leadId    String?
  lead      Lead?    @relation(fields: [leadId], references: [id], onDelete: SetNull)
  note      String?
  createdAt DateTime @default(now())
}

model Note {
  id        String   @id @default(cuid())
  leadId    String
  lead      Lead     @relation(fields: [leadId], references: [id], onDelete: Cascade)
  body      String
  createdAt DateTime @default(now())
}

model StatusEvent {
  id        String      @id @default(cuid())
  leadId    String
  lead      Lead        @relation(fields: [leadId], references: [id], onDelete: Cascade)
  from      LeadStatus?
  to        LeadStatus
  createdAt DateTime    @default(now())
}
```

В `Lead` добавь связи `payments`, `notes`, `events` и поля `dealAmount`
(Decimal?), `dealCurrency` (String?), `firstRepliedAt` (DateTime?).

Категории расходов и валюты — из ответов владельца 13.3 и 13.4. Валюту хранить
рядом с суммой, не в настройках. Деньги только `Decimal`, никогда `Float`.

**Миграции.** Только `prisma migrate dev` на своей базе. Против боевой базы
ничего не запускать без прямого слова владельца.

## 6. РАЗДЕЛЫ

### 6.1 `/admin` — Command Center

Первый экран. Показатели — из ответа владельца 13.6; нет ответа — спроси, не
придумывай. По умолчанию:

- новых заявок за период
- заявки, ждущие первого ответа — самый крупный блок на экране
- проекты в работе
- завершённые проекты
- воронка по статусам: сколько заявок на каждой ступени
- деньги: получено за период, ожидается, просрочено
- последние важные заявки списком, с переходом в карточку

Период переключается: месяц, квартал, год, всё время. По умолчанию месяц.

«Ждут первого ответа» — заявки без `firstRepliedAt`, отсортированные по возрасту.
Это главный экран владельца: то, что горит, видно сразу.

### 6.2 `/admin/applications` — реестр

Таблица всех заявок: номер, имя, почта, тип проекта, бюджет, сроки, дата, статус.

- Поиск по имени, почте, компании, номеру — с задержкой ввода, без перезагрузки
- Фильтры: статус, тип проекта, бюджет, период
- Сортировка по любой колонке
- Постраничность на сервере, по 25
- Состояние фильтров живёт в адресной строке, чтобы ссылку можно было сохранить
- Массовых действий не делать: заявок немного, а ошибиться легко

### 6.3 `/admin/applications/[id]` — карточка

Слева содержание заявки: контакты, компания, цель, описание, функциональность,
ссылки, бюджет, сроки, источник, дата.

Справа рабочая колонка:
- текущий статус и переход по цепочке
  `NEW → CONTACTED → DISCOVERY → PROPOSAL → IN_PROGRESS → COMPLETED / DECLINED`
  (уточнить по ответу 13.2); каждый переход пишется в `StatusEvent`
- **приватная заметка** — только для владельца; никогда не отдаётся публичными
  маршрутами, не попадает в OG и не уходит в сообщения клиенту
- оплаты по заявке: добавить, отметить полученной, увидеть остаток
- лента событий: смены статуса и заметки по времени
- кнопки связи: почта и телеграм клиента открываются в один клик

Первый переход из `NEW` проставляет `firstRepliedAt`.

### 6.4 `/admin/finance`

- Доходы и расходы за период, прибыль как разница
- Оплаты по проектам: получено, ожидается, просрочено
- Задолженности: оплаты с `dueAt` в прошлом и пустым `paidAt`
- Расходы по категориям
- История помесячно, месяц открывается
- Экспорт в CSV, если владелец ответил «да» на 13.8

Что считается доходом — по ответу 13.5. Если валют несколько (ответ 13.3),
показывай каждую отдельно и не складывай их без курса, который ввёл владелец.

### 6.5 `/admin/projects` — кейсы

Список кейсов с состоянием публикации. Создание и редактирование: название,
описание, задача, решение, технологии, результаты, ссылка, объект витрины,
слово-призрак, порядок, галочка «избранный».

Изображения — загрузка в Vercel Blob через `@vercel/blob`, несколько штук,
порядок перетаскиванием, удаление. Ограничения: только jpeg/png/webp, не больше
8 МБ, имени файла не доверять.

Переключатель **Draft / Published**. Опубликованное сразу появляется на сайте:
после сохранения вызывай `revalidatePath` для `/`, `/work` и `/work/[slug]`.

### 6.6 `/admin/testimonials` — отзывы

Добавление, редактирование, публикация: имя, компания, должность, текст, фото или
аватар, порядок, Draft / Published.

Фото нет — монограмма из инициалов, рисуется кодом. Сгенерированные лица не
использовать никогда.

### 6.7 `/admin/settings`

Профиль владельца, смена пароля, при желании базовые контакты сайта.

### 6.8 `/admin/login`

Вход по почте и паролю; почта из ответа 13.1.

## 7. ДОСТУП И БЕЗОПАСНОСТЬ

- Пароль хранится как `bcrypt`-хеш, стоимость не ниже 12. В открытом виде не
  логируется и не возвращается.
- Сессия — подписанная httpOnly-cookie, `Secure`, `SameSite=Lax`, срок 7 дней.
  Либо `next-auth` с провайдером credentials, если это проще и не тянет лишнего.
- **Каждый** маршрут `/admin/*` и **каждый** обработчик `/api/admin/*` проверяет
  сессию на сервере. Проверка в middleware не заменяет проверку в обработчике.
- Ограничение попыток входа: не больше 10 за 15 минут на адрес, ключ — адрес
  сокета, заголовкам прокси не доверять.
- Ответ при неверной паре одинаковый в обоих случаях и не подсказывает, что
  именно неверно.
- Приватная заметка и финансы не отдаются ни одним публичным маршрутом.
- Все изменения проходят валидацию `zod` на сервере.
- Никаких данных клиентов в логах: только идентификаторы и класс ошибки.
- Админка помечена `noindex` и не попадает в `sitemap.xml`.

## 8. QUALITY

**Быстро:** списки и постраничность на сервере, никаких запросов N+1, любой экран
открывается быстрее секунды на реальных данных.

**Надёжно:** любая мутация — server action или обработчик с валидацией;
оптимистичных обновлений без отката не делать; удаление всегда с подтверждением и
понятным текстом, что именно исчезнет.

**Доступно:** вся работа с клавиатуры, фокус виден, заголовки таблиц связаны с
ячейками, контраст ≥ 4.5:1.

**Без багов:** `tsc` чисто, сборка чисто, консоль пустая, на 390 админка пригодна
для чтения и смены статуса.
